# Spec 08 ML recovery journal

Independent audit of the working tree at `4aae04a` on 11 November 2026. Tasks 8.1 and 8.2 are committed. The 8.3 code, tests, migration and ADR were already in the working tree when this audit began. This review used static inspection, recorded PostgreSQL/Worker results, local platform artifacts, GitHub job logs and an in-memory reproduction of the two generators. It did not run training, the ledger suites or Compose again. The recommendations below require a scope decision before implementation.

## 1. Executive verdict

**Choose Path C, a narrower Phase 1 ML gate with targeted V3 fixes.** Preserve the trained FastTree artifact, exact inference evidence and additive finance reducer. They are a credible foundation for a controlled synthetic learned-hold workflow. The classifier is unsuitable as a Friday Ring detector. Its four features contain only amount and source posted balance, and its holdout largely tests transfer-size and balance patterns that the fixture generator assigns by class. Neither a stronger classifier nor more rows from that generator can recover the missing behavioral information.

The `FR-0041` discrepancy has a causal explanation. The Worker screened before settlement and the pure experiment settled after each screen. The two schedules give different integer snapshots for the same payment. The inspected screening transaction and reducer agree on the evidence boundary. No posting or replay corruption was demonstrated. Two separate V3 release issues are visible in code: intake accepts an amount that the model will permanently reject, and certain artifact read failures can escape the typed fail-closed path. Fix these before exposing V3 through the demo’s normal entry point.

**8.4 needs amendment.** Deliver the authorized explanation and observed velocity context now. Defer SSA detection until an independently useful account baseline exists. **8.5 is blocked as a Phase 1 forecast.** Friday Ring cannot supply the specified training history, and the ledger lacks an explicit simulation-time observation boundary for banking actions. Deliver the actual source and branch liquidity trajectories. A conditional projection can follow when the run has known obligations and a time contract. Keep the current Spec 08 exit open until its scope is formally amended and the amended gate is observed. Spec 09 still owns analyst continuation and the browser workflow.

## 5. Fraud classifier failure analysis

### What the model can see

For USD, let `A` be payment amount in minor units and `B` be committed source posted balance before screening. The vector is `ln(1 + A/100)`, `ln(1 + B/100)`, `min(10, A/max(B, 100))`, and `1` when `B > 0 && A >= B`, else `0`. The snapshot hashes feature schema, currency and those two integers. The ratio and drain flag can help a tree find useful interactions efficiently. They add no independent information. Timing, rate acceleration, beneficiary reuse, incoming-to-outgoing pass-through, multi-bank chains, reservations, sanctions and synthetic truth are outside the model input. Posted balance may reflect **effects** of previous settlements, but equal balances erase their history. Coordination and temporal sequence are unidentifiable from an individual vector. [Feature builder](../src/Revenant/Intelligence/RiskFeaturesV1.cs)

### What the holdout measures

The generator redraws the old balance per row, even on repeated accounts. Mule balances use three times the same base distribution and most positive rows take 85–100% of that balance. Ordinary funded rows usually take 0.5–50%, with a small high-fraction tail and separate zero-balance rows. The generator also deliberately produces low-fraction fraud. These are row classes with some shared identities and time placement. Their balances do not evolve through a conserved sequence of settlements. The split prevents direct origin/scenario overlap but cannot remove a distributional shortcut shared by all cohorts.

The audit reproduced `RiskFixture.GenerateCsv(8101)` and the earliest-cohort purge with an independent in-memory SplitMix64 port. Source SHA-256 `52602588079433070176616ca134dcdcb503b117ee712a3baddc6f05a7704623` matches the manifest. Of 3,240 rows, 200 are excluded by transfer type and 100 are purged. Retained counts are 1,817/150 positives (steps 1–143), 609/48 (144–191), and 514/42 (192–239). Posted and amount statistics below are USD major units. Fraction uses the one-dollar denominator floor and cap in the builder.

Opening-balance mule payments of $1,100–$1,490 against $10,000 are only 11.0–14.9% of posted, while 35 of 42 fixture test positives reach 85% or more.

ETL sorts observed steps into chronological windows, assigns source/scenario groups to their earliest split, and drops later conflicts. The parser checks duplicate `(step, origin, destination, amount, old balance)` tuples after normalization. This avoids direct duplicate/origin leakage for the checked fixture, while permitting coincident feature vectors and relationships across destination or unrecorded groups. The duplicate key can collapse legitimate repeats within a PaySim hour and does not surface conflicting labels as a distinct case. Group assignment is source-only when `scenarioId` is absent. The `seen` set also grows with unique rows, contrary to the ETL comment about memory, and the trainer buffers all examples. All three reads need an immutable source snapshot for provenance. The counters can detect some changes across passes, but equal counters alone do not bind each pass to the originally hashed bytes. ### Model and policy decision

Retain FastTree as the small nonlinear baseline. Its tree splits can capture amount/fraction interactions at low CPU and packaging cost. The stored exact-drain 33,136 PPM and $1 from $1,000,000 at 843,525 PPM show that learned scores are neither a drain predicate nor reliable extrapolation outside the fixture. Logistic regression gives a cheaper, inspectable monotonic baseline if constraints and transforms are chosen accordingly. It inherits the same shortcuts and feature collisions. Another boosted tree chiefly changes fitting/regularization and may add deployment cost. A causal velocity rule can detect the deliberately designed burst with exact reasons, but it is a rules policy and needs false-positive testing on legitimate bursts. Compare these baselines before buying a larger model. [FastTree 5.0.1 source](https://github.com/dotnet/machinelearning/blob/a4f730ec0c9106c2c9ef9e1fa34011374115fb98/src/Microsoft.ML.FastTree/FastTreeClassification.cs)

The 8.2 log describes built-in Platt calibration as fitted on training data. The pinned FastTree implementation directly constructs a Platt-form sigmoid with slope derived from the trainer’s sigmoid parameter and zero intercept. The tree is fitted on training data, and the fixture run does not establish independent probability calibration. Show PPM as a fixture-model score. Changing prevalence changes precision even at fixed class-conditional error rates, and the shift here can change those error rates too. F1 assigns no explicit cost to queue load, hold duration, liquidity friction or missed exposure. Tune a later policy against an independent validation cohort, an operational review budget and synthetic cost assumptions. Preserve the artifact, manifest hash, normalization and threshold under their current policy ID. Different ZIP bytes from retraining are a new artifact identity even when reference PPMs agree. [FastTree calibrator implementation](https://github.com/dotnet/machinelearning/blob/a4f730ec0c9106c2c9ef9e1fa34011374115fb98/src/Microsoft.ML.FastTree/FastTreeClassification.cs), [policy catalog](../src/Revenant/Intelligence/RiskPolicy.cs)

For a future behavior model, build v2 features from the same ordered fact prefix in offline reconstruction and serving. Use strictly earlier intake facts for same-origin 5/15-minute counts and sums, prior payer→beneficiary counts and distinct recipients. Use the current candidate only in explicitly named “including current” features. Compute inbound-settlement-to-outbound timing and counts from earlier committed credits to the origin, and rolling fan-in/fan-out from earlier edges in the same tenant/run/branch. Use event-time windows over an observable prefix and a deterministic order for ties. Join outcomes only after computing all feature rows, and purge entire connected simulation episodes across splits. A settlement-dependent feature observes only that branch’s earlier actual postings. Keep identity as a scoped join key and materialize the aggregates and cutoff into canonical evidence. This calls for a new feature and compatible evidence contract, with an additive finance family if the frozen V3 codecs cannot express it.

## 6. Task 8.4 readiness — Amend

The proposed input is one scalar **outgoing intent count per source account per closed five-minute simulated bucket**, scoped by run/account and position. On seed 42 the five emitting mule accounts have nonzero buckets `[3,3]`, `[3,3]`, `[2,4]`, `[2,3,1]`, `[4,2]` respectively. The terminal mule emits none. The first mule starts after 12 five-minute buckets and the last generated intent is 09:58:23 UTC, just under two hours from the 08:00 opening. The entire run offers at most 23 closed buckets at that cutoff if observation was continuous. The latest possible legitimate endpoint for any seed is 150 minutes, still short of 32 buckets. Long runs of observed zeros are real data for opened accounts, but give little support for estimating how an active mule account normally behaves. One burst per mule gives no evidence of a recurring baseline.

The package supports the proposed settings and the CI smoke used them on an artificial periodic series. In 5.0.1 `DetectSpikeBySsa` fits an SSA sequence model, uses the selected error function (signed observed minus expected by default), and derives a kernel p-value from recent residuals. Positive-side, 95 confidence configures an alert on a sufficiently small p-value (about 0.05) after its residual buffer fills. A p-value is neither a fraud probability nor a validated 5% alert rate on this sparse count process. `seasonalityWindowSize=8` bounds relevant seasonality in the algorithm and provides no evidence of a 40-minute periodic pattern. The 32 fit buckets and 16-value residual window have distinct roles. Pin an explicit startup policy and test exact first eligible alert index after loading/reconstructing. Do not count the target bucket as fit data. [Spike estimator](https://github.com/dotnet/machinelearning/blob/a4f730ec0c9106c2c9ef9e1fa34011374115fb98/src/Microsoft.ML.TimeSeries/SsaSpikeDetector.cs), [residual scoring and buffer](https://github.com/dotnet/machinelearning/blob/a4f730ec0c9106c2c9ef9e1fa34011374115fb98/src/Microsoft.ML.TimeSeries/SequentialAnomalyDetectionTransformBase.cs)

Use `localContributions = null` and label the method. If velocity is shown, use the already implemented v7 intake-time rolling count and window, linked to that intent’s ordered prefix. Present the count as a deterministic observation and distinguish a rule firing from descriptive context. Check operator/supervisor authorization and cross-tenant denial, exact arithmetic under tied timestamps and run/fork boundaries, and no labels or comments in the explanation payload. Report the deferred anomaly as unavailable. No detector or advisory evidence is required for the finance fold. [Case authorization](../src/Revenant/Payments/RevenantLedgerService.cs), [existing rule calculation](../src/Revenant/Timeline/FinanceLedgerReducer.cs)

**SSA re-entry.** Pin bucket origin, `[start,end)` interval, observation watermark, fact prefix, clock, and treatment of late or boundary events. Zero-fill only intervals that were observed. Keep missing history distinct and emit typed `InsufficientHistory` through cold start, short or missing windows and unsupported baselines. A fully closed bucket may contextualize a later case and cannot explain the earlier decision using payments that arrived after it. Store both detection and decision cutoffs if attaching it retrospectively. A reproducible explanation can show the actual closed count and a separately named prior observed rate. If describing the model residual, use its actual signed residual and aligned prediction. Handle zero baselines without a ratio. Compare the alert rate per account-hour and detection delay against a pinned count/rate rule and an IID spike baseline on separate longer normal, legitimate burst, idle and injected-burst scenarios. IID spike removes the seasonal fit but still needs sufficient comparable residual history and handles changing event rates poorly. Reopen SSA only if it earns an advantage at a stated alert budget on independent runs. Document generated prehistory and keep it out of ledger facts. Snapshot the advisory configuration, scoped series hash and resulting evidence for reproducibility across restart/branch, with an explicit numeric contract if displaying recomputed outputs. ## 7. Task 8.5 readiness — Block as written

**History and time.** `windowSize=8`, `seriesLength=32`, `trainSize=96`, `horizon=8` are legal and were exercised in the smoke. Training requires 96 usable five-minute observations, or eight hours. At Friday Ring’s last intent the run has at most 23, including quiet buckets. At that length there are at most 15 endpoints with eight subsequent observed buckets even with an already fitted model and a first origin after one observed bucket. Those overlapping endpoints and the six interacting banks are not independent. A branch shares the source prefix and adds fewer distinct observations. Fitting on artificial prehistory is lawful for a clearly identified repository-generated experiment if it predates the cutoff, matches units and is kept separate from authoritative facts. Anchoring its level to $110,000 opening per bank does not establish comparable drift, flows or hold dynamics. A sinusoid fit can validate mechanics only. [Forecast estimator](https://github.com/dotnet/machinelearning/blob/a4f730ec0c9106c2c9ef9e1fa34011374115fb98/src/Microsoft.ML.TimeSeries/SSaForecasting.cs), [SSA sequence model](https://github.com/dotnet/machinelearning/blob/a4f730ec0c9106c2c9ef9e1fa34011374115fb98/src/Microsoft.ML.TimeSeries/AdaptiveSingularSpectrumSequenceModeler.cs)

V2/V3 fact position is the accounting order. The simulated ledger clock advances on intake. Screening, review, settlement and return can follow at later fact positions while that clock remains unchanged. Backdating those effects to the intent timestamp leaks state. Host commit times and Redis delivery do not establish simulated-time bucket completeness. Before any regular-series acceptance, specify a replayable `(position, simulated time)` observation rule with a watermark or explicit observation ticks and same-time ordering, plus a real end-of-run observation. Either adopt the fold’s clock with explicit limitations or add a versioned timing contract if action time must be distinct. Never manufacture observations by carrying forward through unobserved future buckets. [Ledger reducer](../src/Revenant/Timeline/FinanceLedgerReducer.cs), [ordered fact append](../src/Revenant/Payments/PaymentLedgerStore.Cases.cs)

**Financial target.** Use per-bank USD `Σ posted − Σ active reserves`, with integer authority. Creating a hold lowers the origin’s available balance without changing posted. Reject/release restores availability. Settling a fully reserved payment lowers source posted and releases the same reserve, so the source’s available balance is unchanged by the settlement itself, while the destination’s rises. A clear unreserved settlement changes both sides’ available balances. A legal compensating return moves posted money back. If a test expects every action to change every bank’s available trajectory or point forecast, the test violates this accounting. The ledger enforces nonnegative availability for valid runs. An SSA prediction below zero would represent out-of-support extrapolation on this target. It cannot validate a warning of an observed overdraft. A useful future warning can predict falling below an explicitly pinned positive operating buffer, or expose the size of an unmet **specified** obligation under a conditional flow scenario. Aggregate bank balances can also mask account-level insufficiency. [Balance and availability guards](../scripts/db/migrations/revenant/0003_holds_settlement.sql), [settlement and returns](../src/Revenant/Payments/PaymentLedgerStore.Settlement.cs)

**Model and verification.** The proposed SSA is univariate. Nonadaptive inference can consume new buckets and change forecast state while keeping fitted coefficients fixed. A loaded model with no updates will not see a branch divergence. A valid proof compares the correct bank’s changed bucket series and independently advanced states from the same pinned artifact. Some differences can legitimately yield the same forecast. Start at a verified position, vary a legal action whose effect changes a completed bucket, and assert causal inputs and forecast recomputation. Keep state isolated by tenant/run/history/bank/cutoff. ML.NET bounds use estimated noise moments and a normal quantile for each horizon. Their nominal 95% is model-conditional marginal coverage and supplies no simultaneous 40-minute path guarantee. Require rolling-origin MAE/RMSE, interval coverage and width by horizon and bank, and a persistence baseline on held-out runs. Use only information available at each origin. Count observations and distinct runs, state dependence and label the seeded cohort. Publish `InsufficientHistory` or incompatibility when inputs cannot support the defined method. [Forecast implementation and bounds](https://github.com/dotnet/machinelearning/blob/a4f730ec0c9106c2c9ef9e1fa34011374115fb98/src/Microsoft.ML.TimeSeries/AdaptiveSingularSpectrumSequenceModeler.cs)

**Phase 1 replacement.** Show authoritative posted, reserved and available curves from source and branch at aligned facts, with observed simulated time as display metadata. Expose forecast unavailability. If a forward view is subsequently needed and legal future obligations are known at cutoff, the smallest interpretable method is current available plus the hypothetical change in posted minus the change in reservations for an explicitly selected schedule. Use only obligations known at the cutoff, or label user-assumed actions, and show one path per named condition. With no schedule, persistence is a baseline. These methods yield no statistical intervals and cannot infer unobserved future arrivals or approvals. Any forward view is informational and has zero ledger-write capability.

**Platform re-entry.** `Revenant.csproj` currently includes FastTree but not TimeSeries. `Worker.Dockerfile` uses Alpine/musl, and Compose does not pin Worker to AMD64. When SSA is justified, package the same Worker for glibc Linux AMD64 with the exact MKL/OpenMP dependency chain, confirm `ldd` and mapped libraries in the deployed process, and exercise fit/load/predict with the actual runtime image and native x64 CI. Keep model fitting offline. Measure cold load, series reconstruction and per-bank prediction wall time, CPU and RSS for six banks and two concurrent histories, including restart and isolation. Set a bounded cache/reconstruction budget from those measurements and keep advisory computation off the financial lock path. Emulated SDK smoke covers platform preflight. Production packaging, load and repeatability remain unmeasured. [Worker image](../deploy/docker/Worker.Dockerfile), [Compose](../deploy/compose/docker-compose.yml), [platform job](https://github.com/nightwing9-bit/the-sands-of-time/actions/runs/43000045750/job/130453630864)

## 8. Task 8.6 and Spec 09 risks

- **Run opening and visibility.** `RevenantLedgerService.OpenRunAsync(..., modelAware: true)` exists, but the HTTP handler and request contract only open V2. The store accepts V3 even if the Worker cannot load the pin. A missing artifact then leaves Initiated payments, and `CloseRunAsync` returns `RunNotQuiescent`. Current operator evidence is the typed Worker log, not a public V3 availability response. Before demonstrating normal V3 operation, use an explicit, authorized launch path with verified readiness and typed unavailability. Resolve the existing fresh-run operation with Spec 09 so the UI contract has one owner. Keep a separate explicit V2 run available. [Run API](../src/Revenant/Api/RevenantLedgerApi.cs), [run store](../src/Revenant/Payments/PaymentLedgerStore.cs), [closure](../src/Revenant/Payments/PaymentLedgerStore.Closure.cs)
- **Pins across upgrades.** The live row pins the finance family. Worker and projector map every `/3` to the hardcoded catalog V1 pin. The Timeline context contains the full policy/model identity. That is stable while `/3` permanently means this pin. Changing the singleton mapping would change the meaning of a recorded live run, including one created before its first projection. Before offering a second policy, resolve an immutable per-run pin or add a new family with a permanent mapping. Retain historic policy entries and compatible codecs. A new feature/evidence schema needs a compatibility ADR and an additive version if current canonical bytes cannot express it. Replaying an old run should require the historical context and codecs. Executing new inference needs the verified ZIP, manifest and supported runtime. The existing replay resolver does not read ZIP bytes, so losing only the scorer assets can leave historical replay healthy while new V3 screening and branch inference fail. [Risk policy catalog](../src/Revenant/Intelligence/RiskPolicy.cs), [projector open](../src/Revenant/Projection/ModelLedgerProjector.cs), [V3 context](../src/Revenant/Timeline/ModelLedgerFinance.cs)
- **Bounded V3 branch proof.** Use the same policy and model pin on both histories. Fork a verified source immediately after a real hold. Exercise legal reject/release on one side and approve/settle on the other, then screen the same next exogenous payer intent at each side’s own causal position. Choose a source account whose posted balance changes and check that the child produces a different raw feature hash and newly computed exact evidence. PPMs may coincide on different feature vectors. Use inherited prefix state identity for the reducer and child history identity for output/operational scope. Reject stale source evidence even when intent IDs match. Record source fingerprint before/after, no live writes under real role grants, and byte-identical cold replay for source and child in a separate process with no predictor invoked. Remove a required codec/context pin for an incompatibility control, and a scorer artifact for a new-inference failure control. A reserve-only change leaves `risk-features-v1` unchanged. The current catalog accepts one pin, so design §6’s suggested threshold/policy variation is unnecessary for this causal proof. Neither durable family can run a v8 continuation by swapping context. Preserve run and history identities in the UI. A computed branch trajectory is historical/counterfactual accounting evidence, distinct from an SSA forecast.
