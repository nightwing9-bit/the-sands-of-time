# Phase 1 execution playbook

**Do this in order:** 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 → 11 → 12 → 13. The DAG permits some parallelism (e.g. 07 with 10 after B2), but this strict order is simplest for a credit-limited solo builder and avoids context switching. Spec-01 is the only allowed starting point on a greenfield repo. When an actual existing repository already satisfies a prerequisite, **verify objective exit gates rather than recreating files**.

For each task: read the current spec's `requirements/design/tasks.md`; inspect *specified* code paths/dependency contracts; implement one task with interfaces unchanged; run listed checks; mark task `[x]` **only after actual evidence**, document required issues briefly. Kiro can inspect files beyond an initial list when an actual dependency demands it; don't force whole-repo ingestion. Assign a model based on risk; strong model for engine/public schema/finance/multiplayer; normal model for narrow plumbing/UI once tests freeze behavior. Do not regenerate architecture or spec docs from scratch in a Kiro chat.

**Actual first action:** initialize repository root (`git init` if appropriate) and copy `.kiro/` plus `docs/`; open `.kiro/specs/spec-01-foundation-bootstrap/requirements.md`, `design.md`, then `tasks.md`. Start `1.1` to establish runtime solution, Vite apps, Compose, `.github/workflows/ci.yml`; do not start spec-02 before `01` dependency/CI and clean Compose smoke are observed. Use `Context7` only for precise .NET/EF Core details. The first real git commit should include `.kiro/`, LICENSE selection, run instructions and an actually passing smoke check when possible.

- **B1:** `dotnet test` critical foundation suites; clean migrations/Compose; one complete test-only Timeline fake reducer replay/branch; sessions/identity/outbox transport tests; shared scrubber mounted by two adapters and typed client handshake. Gate reports actual not invented test commands and results.
- **B2:** Specs 05 and 06 each finish their **own** independently runnable slice first; **only at the B2 basket gate** test both together. Six-bank synthetic seeded v7/v8 produces causal changed outcomes in actual finance pure reducer, source hash untouched; game 90s solo original can be restored at a nonzero-charge tick, branched, played on with same schedule and compared; both invoke exact same Timeline assembly and scrubber component.
- **B3:** DB enforced complete balanced posting groups & concurrency, idempotent settlement, staff multi-actor control, versioned ML.NET with held-out evaluations, live causal liquidity forecast, replay DB-role write denial, explicit post-fork analyst-action policy, deferred-versus-prevented metric accuracy, two non-destructively repeatable scenario runs, real isolated financial branch, all five screens with actual navigation and audit verification.
- **B4:** real 2–4 connected browser multiplayer with lobby/invite/ready/forfeit/rematch and spectator denial, durable verified solo histories/branches/sharing, rating exact-once effects, all Ghost Lap UI flows desktop/mobile/Pixi, actual shared Timeline interaction and browser traces.

**Cross-app checkpoints:** C1 after spec-02 test-only two reducers; C2 after spec-06 both real adapters/source immutability; C3 after spec-09 finance correctly persists/projections, matched against Ghost verified game history; C4 after spec-13 demo-click path and source-import verification. **Late public submission/deployment gate (not a new Phase 1 spec):** After Spec 13, the deploy/submission owner runs the already-planned single-instance Compose stack behind HTTPS; verifies both distinct apps from an **external** browser, judge-access credentials/MFA instructions, health/secrets/configuration, a fresh Friday Ring run without ledger reset, a real Ghost Lap guest/solo branch, actual public URLs, public GitHub/LICENSE/`.kiro` inclusion, and an under-three-minute demo. Record observed evidence; do not mark Phase 1 code complete as proof that hosting is live.
