These are **planning ceilings, not usage measurements or predicted fixed token-to-credit conversion**. Actual pricing, model availability and credit debit depend on the user's Kiro account/plan and must be read in Kiro at execution time.

| Basket | Planned credits | Main difficulty | Model allocation |

| **Total** | **4,000** | | |

**Checkpoint and recalibration:** after 01, 02, 05 and 06, record actual credits/task, first-pass tests, corrections and time; re-estimate remaining tasks. Do not force weak models through repeated failed cycles merely to save a small per-invocation charge. Route strongest effort to irreversible public contracts, ledger transactional SQL, causality, deterministic restore/hash and room ownership; normal models to bounded UI, DTO mapping, wiring and document edits. Keep one active spec and one dependent task at a time; use narrow file paths/contract docs instead of re-injecting master context. Parallelize independent UI scene/CI scripts **only when they edit disjoint files and frozen contracts**; never concurrently modify migrations, Timeline contracts, game rules, settlement logic, source manifests or the same EF DbContext.

**Cut policy:** if credits become strained, first remove redundant agent calls, repeated context loading, redundant test loops and premature polish; use local tests/CI without inference. Do **not** silently cut a locked Phase 1 feature or falsify its outcome. Any scope change requires explicit user decision and coverage map update. The 550 reserve protects integration and visible demo integrity, not speculative enhancements.
