# Spec 10 design — Authoritative multiplayer, fair simulation, resilient realtime performance

## 0. Architecture decision and scope

This is **planned V2 implementation**, not an assertion that V1 or these specs have passed. Specs 03/06 and `docs/architecture/01-master.md`, `02-spec-map.md`, `03-contracts.md` own already-established public contracts. Before edits, inspect their real source, migration/schema, exported API and golden tests. **Freeze Marrow and completed Revenant**. Gameplay may be extended **inside Ghost Lap** with new rules/layout identity; never patch V1 `ghost-v1` serialized formats/recorded hashes to facilitate multiplayer. Single Realtime replica only; no leader-election framework, multiowner topology, MP input archive, ghost as network participant, or frontend-derived score. Spec 13 is not an implementation dependency here.

### Architecture contracts to settle during preflight (blocking before 10.2)

Produce a short factual compatibility matrix mapping: existing Spec-06 reducer/codec/state/hash; phase order and positional physics; input quantization/latch/edge state; `ghost-v1` golden fixtures; Spec-03 stable guest principal/reconnect token; existing host ownership and Realtime ingress; existing `ghostlap` migrations; Postgres session-guard and database roles. **Do not guess class names or implement speculative API changes.** If a frozen port cannot meet a requirement, identify a compatible Ghost-Lap-owned adapter/rules version and record a focused decision **before** writing dependent code. Any unresolved wall-occlusion, contact/Burst phase order or scoring coefficient from foundational context must be explicitly pinned in the new MP rules profile; preserve existing solo rules rather than silently selecting a different interpretation. No game-brand redesign.

## 1. Ownership, host and state machine

`Created -> Lobby -> Countdown -> Running -> Finishing -> Finalized`; `Countdown -> Lobby` on required dropout; `Running/Finishing -> PendingFinalization (provisional) -> Finalized OR Aborted/Unrated` after an authoritative terminal decision. `PendingFinalization` may be a **transient observable status**, not a separate contradictory final receipt. `Aborted` has no winner/rating, including unrecoverable overload. Timeout and exits in Lobby/Finished are bounded; stale room objects expire. Finished result remains readable after Realtime crashes because PostgreSQL is authoritative.

- Lobby has 2–4 actual competitor slots (not four mandatory), separate bounded read-only spectators; verified principals uniquely own slots. Start requires all enrolled 2–4 competitors connected/ready and host authority. During Countdown competitor joins close and loss cancels; guests may observe if allowed. Host leaving Lobby transfers to earliest joined connected player; empty expires. Invite code is unpredictable, expires, lookup rate-limited, and not an alternative authentication credential.
- Countdown config initial 3 s; seed, fair spawn IDs, rules/layout/hash, **opaque ranking algorithm ID** (initial `elo-pair-v1`, interpreted only by Spec 12), roster, 2700-tick target, authority epoch and prospective match ID are sealed before kickoff. The **start receipt** commits at the transition to Running, before sending `MatchStarted` or accepting tick-0 moves. A cancelled countdown creates no rated start receipt; a failure to persist leaves Lobby safely retryable. An acknowledgement loss recovers using the sealed match ID and receipt lookup, never creates a second result-bearing start.
- One long-lived `IActiveRoomOwner` per Realtime host, one serial mailbox/loop per room. Hubs are ephemeral ingress, not stateful tick owners; API commands forward securely to that existing owner via the configured runtime path, not instantiate a competing owner. State transitions use CAS/lifecycle version and request IDs; duplicate start/rematch requests return same result or typed conflict.
- **Process exclusivity:** deployment configured one Realtime authority replica. Hold a dedicated **session-level** PostgreSQL advisory lock on a continuously monitored, nonpooled-for-lifetime connection; do not mistake transaction-scoped lock for the guard. If guard disappears/monitor fails, stop admitting room commands, cancel ticks/finalizers and reject activity until safe restart. Host startup must refuse misconfigured >1 replicas and a second process failing guard acquisition. Losing a guard need not instantly silence stale clients: safety comes from durable generation fencing and client epoch rejection, not a claim of perfect broadcast fencing.

### Durable generation fence and final result serialization

`ghostlap.match_session` is minimal start identity, not a match log: `matchId` PK, `roomId`, sealed immutable roster/config digest and seed/rules/layout/ratingAlgorithmId, `startedAt`, `generationId`, `terminalDecision` (`Started`,`ResultCommitted`,`Aborted`), `terminalVersion`, timestamps; unique `matchId`. `ghostlap.realtime_generation` contains process generation and retirement state. On startup, after session lock acquired, register a new generation and **atomically retire/abort all predecessor unfinished receipts through the same transaction/row-lock order used by finalizers**, before new matches. A deliberately committed prior result must remain committed. The replacement does **not** take over or reconstruct live multiplayer simulation.

Finalizer begins a database transaction, locks the corresponding `match_session` row, validates generation still active/not retired and terminal `Started`, then commits terminal `ResultCommitted`, unique `match_result`, and one unique outbox `MatchFinalizedV1` **within that same transaction**. Retirement/abort acquires the same receipt lock and checks current terminal. Old-first finalization wins only if committed before retirement; replacement-first retirement prevents any subsequent stale result. A stale in-memory check is not an acceptable fence. Idempotent identical finalization returns committed result; differing payload for same `matchId` is a conflict + alert, never a silent overwrite. Outbox publishes only a valid finalized match; delivery is at-least-once, actual rating effect is owned by Spec 12.

If PostgreSQL is unavailable, don't start a new ranked session. At end of a running match, pause **only the finalizer**, not the serialized simulation; show `PendingFinalization` with bounded attempts and backoff while the generation is valid. A `Pending` response never claims committed `Aborted` or rated result. After loss of authority, restore receipt terminal truth from DB when available: committed result stays, uncommitted predecessor is transactionally marked `Aborted`, and unknown match IDs are `NotFound`, not `Aborted`. If DB remains unreachable, report **unverified provisional unrated state** rather than forge a durable terminal. The UI can offer a fresh room/rematch; no abandoned old match later gets rated. Don't place synchronous DB work in a tick step.

## 2. Canonical world, high-speed physics and exact time

- **Authority:** `GameRules` is the sole deterministic game transition function. 2–4 player state is a versioned Ghost-Lap multiplayer extension using Spec 06's existing geometry/schedule/scoring phases; it is not an independent gameplay reimplementation. All updates apply in stable `(canonicalTick, phase, slotId, stableEntityId)` order, with stable tie breaks for same-tick candle claims and contact. Rule identity pins every gameplay-significant decision. Document actual Spec 06 phase order before extending it; if 06 does not define multi-actor order, define only missing MP ordering in the versioned extension. Tick 0 is initial state; each simulation step takes effective inputs for tick `t+1` and produces state `t+1`; terminal state after tick 2700 includes whichever actions the sealed version's declared phase order permits there.
- **Gameplay identity:** fixed full-arena 16:9 open movement, short walls, 2/3/4 balanced sockets; identical physical players independent of cosmetic character; 0–4 charge; candle schedule from seed+rules+layout independent of collection; contact weaker loses charge only under pair cooldown; four-charge manual/expiry auto-Burst once, score penalty clamp, no stun/elimination. No invented ghost damage, bombs or enemy AI. Wall occlusion and tuning values need a sealed rules policy before active competition, not deferred to renderer.
- **Speed safety:** derive `d_max` from maximum movement/acceleration, diagonal normalized vector and the fixed 1/30-s step; inspect collider radii, thinnest wall and pickup/contact geometry. For every allowed move prove either deterministic continuous/swept intersection/substep handling or a conservative displacement envelope for **all** wall, player and candle interactions. Endpoint-only non-overlap is not proof. Include oblique corners, glancing slides, head-on crossings, starting overlapped, wall penetration correction, and simultaneous claims. Preserve old 06 fixtures; any algorithm upgrade creates new Ghost-Lap-owned rules identity and replay fixtures, not changed historical state interpretation. Test score only from actual player-driven post-collision displacement, excluding depenetration, external snap and interpolation. Prevent zero-cost corner looping from dominating contested candle play through measured scoring coefficient balance, not secret speed changes.
- **No extra wall time awards:** use server monotonic clock for cadence, `tick` as authoritative progression. Each logical tick is a fixed 1/30 s, and every tick includes deterministic scheduled auto-actions. On scheduler delay, advance **all** logical ticks in order; bounded catch-up (initial policy max 3 immediate ticks per scheduler iteration, configuration subject to load evidence), never skip ticks or award distance by `realElapsedTime` multiplication. Track drift; if sustained backlog cannot be repaired within the configured limit, terminate via legitimate fenced `Aborted/Unrated` rather than indefinitely run 90 s of score over arbitrarily slow wall time. Initial illustrative alarm: lateness >2 ticks for multiple consecutive samples; **final overload duration/threshold is a measured deployment setting, not a new GameRules constant**. Any abort path uses the same terminal receipt fence and no ranking outbox. Late connection input is never retroactively placed in an already committed tick.

### Input admission, fairness and controller takeover

Each authenticated competitor has one authoritative slot and one **controller epoch**. A new authorized controlling connection during grace atomically supersedes the old epoch; any old socket can view if permitted but cannot submit control. Race the takeover against queued old commands; reject commands tagged with a superseded epoch at admission/dispatch. Session principals are verified server-side; reconnect credentials are not ordinary invite links.

`MoveBurstInput(matchId, controllerEpoch, targetTick, seq, directionQuantized, requestBurst)` is a conceptual envelope, not authority over coordinates. Accept strictly increasing `seq` per controlling slot, a bounded server-relative target tick window, finite normalized/clamped vector and bounded input rate. Explicitly define the configured future/past windows and how server-tick offset is estimated **from authenticated server snapshots**; they must be measured at representative RTT/jitter before freezing a game network profile. Inputs queued for a tick are resolved in stable slot order; for multiple admissible packets per slot/tick the **highest accepted sequence before that tick's cutoff** supplies the movement state, and an admitted Burst rising edge may fire at most once according to pinned edge semantics. No packet arriving after tick commit can change that tick; dropped/late packets are acknowledged/rejected with typed reason. Acknowledgements distinguish *received*, *admitted*, and *applied*; avoid telling a client its input affected play merely because transport accepted it.

For *connected* player without newly accepted input, Spec 06's held-direction clock is measured in **logical ticks**, lasts at most six, then neutral; stale duplicate packets never renew it. Burst edges are not held/replayed. A disconnection event immediately neutralizes direction/Burst at the next authoritative processing boundary; grace remains 450 logical ticks. Because six ticks can move a fast player far, measure stale-input travel at maximum legal speed and network tests with key release, dropped packets and tab suspension; change hold only under new versioned mechanics with V1 fixtures intact.

## 3. Snapshots, authoritative gameplay events and transport backpressure

Snapshots are **read-only projections**, not replay archives: `(roomId, matchId, generationId, lifecycleVersion, serverTick, snapshotSequence, rules/layout IDs, roster status, positions/velocities, authoritative score breakdown, charge/Overlit, active candles, per-recipient applied input seq/controller epoch, server time anchor)`. Clients discard older generation, match, lifecycle or snapshot sequence. Initial cadence every two ticks (~15 Hz), adjustable up to 30Hz only after bandwidth/latency measurement; renderer can aim at 60+ FPS using local prediction + correction, remote interpolation. Prediction may use a thin compatible representation but never creates authoritative gameplay state. Expose a bounded resync snapshot and control acknowledgement after reconnect; do not force visual response to wait for RTT.

Gameplay feedback events derive from **resolved** authoritative simulation, e.g. `(matchId, generationId, tick, perTickEventIndex)` + event kind, actors, location, authoritative effect and rules version for Candle/Overlit/Burst/Contact/Score/Finish. They are semantic cues for later FX/audio/expressions, **not** a separate cosmetic mechanic, input log or a Spec-13 design. Client deduplicates event IDs; a reconnect obtains current state plus bounded recent event tail if available, without claiming every cosmetic effect is persisted. Reliable final/result/lifecycle notices should be idempotently refetchable from authoritative state.

A tick only computes world change and enqueues bounded immutable publication work. Serialize/fan-out asynchronously with backpressure, not `await` individual socket writes/SQL in the reducer. Coalesce obsolete positional snapshots for slow recipients; **never** coalesce terminal decisions, trusted applied-input acknowledgements or critical membership transitions without a safe refetch path. Per-room/per-client queue caps and spectator caps are explicit configuration; over-budget clients degrade to reduced snapshot frequency, resync or typed disconnect. A congested spectator must not delay competitors. Any chat delivery belongs to a different bounded lane (Spec 12). Track bytes, queue depth, drops, resyncs, CPU and GC.

## 4. Disconnect, finish, placements, ranking handoff

On verified disconnect, neutral input immediately; player remains a normal collidable/collectible/auto-Burst-eligible participant through **450** ticks (grace expires at the precisely documented tick boundary). After expiry, freeze all score components and stats and mark forfeit. Remove forfeited players as actor and target from motion, wall/player collision, pickup, contact, Burst and pending Overlit auto-action. Never reinstate gameplay on reconnect after forfeit; spectator-only until a new match. Remaining players continue through normal final tick even when fewer than two connected; no prematurely invented result. Tests cover exact tick 450, 451 and forfeit while Overlit.

**One canonical competition order for Spec 12:** finishers always above forfeits; among finishers, greater authoritative final score wins; among forfeits, greater frozen score ranks higher. Scores equal within the same status class produce a **genuine tie** (pairwise outcome 0.5). Stable slot is solely a display order and tie-safe serialization key, never an artificial competitive advantage. A match with no nonforfeiting finisher is marked **unrated** even if its summary is finalized; a single nonforfeiting finisher and ≥2 distinct eligible starters may be rated under this explicit casual policy. Other eligibility checks (distinct authenticated guest principals, valid start receipt, anti-abuse limits) are sealed into immutable result evidence, not recomputed from who is currently online. Network/service-side abort is never a player forfeit. Keep rating eligibility/placement policy versioned and auditable.

Canonical `MatchResult` carries `matchId`, room/generation, sealed roster/participant identities, seed/rules/layout/hash, tick count/start/finish, status, per-player score and distance/pickup/penalty/charge/Burst/contact stats, `forfeited`, `competitivePlacement` including ties, `ratedEligible` and `eligibilityReason`, `ratingAlgorithmId` pinned at start, result digest computed from canonical server-generated field ordering and numeric representations (not platform-default JSON ordering), and terminal version. No client-supplied results. `MatchFinalizedV1` is emitted only with atomic result transaction; Spec 12 uniquely owns actual rating receipt/effect application. The rating worker must not select an algorithm from its current deployment default for a historic delayed match; it validates the result's sealed `ratingAlgorithmId`. No full MP per-tick journal. Rematch issues fresh match/seed after explicit roster ready, never reopens a terminal receipt or rating event.

## 5. Operational tests and measurable acceptance

- **Security/lifecycle:** 2,3,4 separate authenticated sockets, ready/countdown/dropout/host handoff; invalid/repeated commands; two browser tabs with controller takeover; forged spectator/foreign slot; membership revocation.
- **Simulation proofs:** existing `ghost-v1` hashes unchanged; MP same seed+canonical applied inputs yields same state and event IDs; max-speed swept/multi-contact/pickup property cases; no score from collision corrections; 2/3/4 spawn reachability, simultaneous deadline/Burst/contact/candle, full 2700 ticks.
- **Authority fault injection:** lose only old dedicated advisory connection while old process and normal pool remain alive; replacement retires old receipts; race old result commit both orders and verify only one terminal decision/outbox; test failure before start commit, before result transaction, after SQL before ACK, after commit, while DB unavailable and after process death. Fresh match result after rematch is independent.
- **Performance profile:** at least four simultaneous 4P rooms and two spectators each in the target host/profile (record hardware/config, or document explicit blocker); 30 Hz logical stepping, 15 Hz default snapshots, p50/p95/p99 step CPU + start lateness, catch-ups, overload abort, GC/queue depth, byte rate and input-to-applied telemetry under 50/150/300ms RTT plus loss/jitter. Target p95 tick start lateness <1 tick and p99 <2 ticks during normal measured load, no permanent backlog; if not met, Spec 10 remains incomplete. Test slow spectators and backpressure independently. Numbers are acceptance **targets**, never fabricated measurements.
- **Game feel:** side-by-side active candle contest vs corner-distance exploitation at sealed score weights; actual fast wall slide and no stuck corners; 2/3/4 seed fairness; record findings and adjust **new** MP version only if needed, not `ghost-v1`.

**Implementation gates:** all API/Realtime DB roles and policies coexist with Revenant, no frozen shared change, real Testcontainers/real sockets where appropriate, evidence paths and exact tests recorded in `docs/kiro-log.md`. Do not mark unexecuted assertions as passing.
